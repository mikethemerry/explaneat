XOR: one signal, six minimal ReLU realisations

On the four data points, XOR is a single signal. A PropNEAT network with one ReLU hidden unit and skip connections realises it in two families. Within a family you can move continuously from any solution to any other without ever breaking XOR. Between families you can't. The two families are genuinely different mechanisms: a linear count with a corner correction, and two symmetric halves of XOR. They stay two realisations, each with three cells. The LP enumeration's six "classes" are cells inside these families: they record where the hinge's fold sits relative to the four data points, which is what gives the hinge its Boolean name. All weights shown are hand-chosen representatives, checked on all four rows. They are not the solver's or the evolved weights.

Why this page exists

Reproducibility needs a better word than "same"

The thesis works with World →A→ Model →B→ Explanation. We want to trust A, the model's fit to the world, and we get there through B, an explanation we can verify against the model. Reproducibility asks whether running A ten times gives ten equivalent models. Cox regression converges to the same model every time. PropNEAT does not: different seeds give different networks that can still make the same predictions.

So equivalence needs a definition between "same predictions" and "same weights". A signal is what a model uses, identified on the training data. A realisation is a subgraph with its weights and activation that computes it. Realisations of one signal agree on the data and can disagree everywhere else, between training points as well as beyond them. XOR is the smallest case: one signal, two families (a ridge and a valley), each with a ReLU or a sigmoid hidden unit. That gives four shapes, all identical on the four data points. Which one is preferable depends on the use, and choosing deliberately needs both an explanation that says two parts carry the same signal and a way to test it by changing the model.

The full argument, its relation to the Rashomon set and the evidence from the 10-seed and churn experiments are in README.md, which sits beside this page in the ExplaNEAT repository (docs/signals-and-realisations/).

Architecture (minimal: one hidden unit, skips allowed)
h = ReLU(w₁x₁ + w₂x₂ + b)
z = v₁x₁ + v₂x₂ + u·h + c,  ŷ = σ(z)

Every panel on this page has a ReLU hidden unit and a sigmoid output, as PropNEAT builds them. The sigmoid only turns the score z into a probability, so the decision is the sign of z. A threshold unit means a hidden unit with a step activation (or a sigmoid steep enough to act as one). It appears here only as the comparison case, with 2 classes. None of the six panels uses one.

Two discrete things describe a solution: the sign of the hinge's output weight u, and the hinge's active set P (the rows where its pre-activation is positive). The sign of u decides the family. To change it, u must pass through 0, where the hinge is cut off, the network is linear, and XOR fails. The active set decides the cell. It changes whenever the fold slides past a data point, which can happen continuously while XOR holds throughout. Counted under input swap x₁↔x₂ and complement x→1−x, there are 2 families and 6 cells.

Definition

Hinge

A hinge is a ReLU unit, h = ReLU(w₁x₁ + w₂x₂ + b). It is exactly zero on one side of the line w₁x₁ + w₂x₂ + b = 0 and rises linearly on the other. That line is the hinge's fold. The data points on the rising side are its active set.

With one input, a hinge is a line with a single kink, like the capital-gain penalty in Adult or the service-calls threshold in churn. With two inputs, it folds the plane along a line. A single-input hinge here is one whose active set is the rows where one input is 1, while its slope still depends on both inputs. That's how it passes different values on its two active rows.

Each card's plot shows σ(z) over the input plane: blue where the network predicts 1, magenta where it predicts 0, pale where it is unsure. The dashed line is the hinge's fold, with h > 0 marking the active side. The outlined square is [0,1]², and the four dots are the data: filled for XOR = 1, open for XOR = 0.

The realisations

Two families, each sliding through three cells

The skips alone give a linear score. XOR isn't linear, so that score always gets one row wrong, and the hinge exists to fix it. Family 1: the skips compute OR, so 11 is wrong, and the hinge pulls it down (u < 0). Family 2: the skips compute x₁ ∧ ¬x₂, so 01 is wrong, and the hinge pushes it up (u > 0). Each family keeps one sign pattern throughout. Drag the slider to move the network along a path of XOR-solving networks: the fold slides past data points, the hinge's name changes, and the prediction on the four rows never does.

Under each network, the two small plots split the output into its parts: what the hinge outputs on its own, and what the skips score on their own. Read on the four data points, each part is a logic gate. In Family 1 the skips are OR and the hinge flips exactly AND, so XOR = OR ∧ ¬AND. In Family 2 the skips are x₁ ∧ ¬x₂ and the hinge flips exactly x₂ ∧ ¬x₁, so XOR = (x₁ ∧ ¬x₂) ∨ (x₂ ∧ ¬x₁). This holds at every point along each slider path (checked at 1,000 points). Moving between cells changes which rows the hinge fires on, but not which rows it flips: as long as the weights stay in proportion, the extra activation never changes a sign. The network is a composition of two logic gates. The cell only changes how the correcting gate is drawn.

Why the threshold case has 2 and ReLU 6: a step unit can't pass different values on two active rows, so the middle column is missing, and σ(−z) = 1 − σ(z) merges the outer two. ReLU keeps all three cells, but they stay inside the same 2 families. The families are the realisations; the cells are how a hinge happens to be named. Path check: straight-line paths between the cells of a family keep XOR with margin ≥ 0.67 (2,000 steps per segment). Every straight path between families breaks it, as the u = 0 argument predicts.

Which diagonal the fold runs along is the ground truth of how each family composes XOR. Family 1 thresholds the count of 1s, x₁ + x₂, which varies along the main diagonal: XOR is the band 1 ≤ x₁ + x₂ < 2, so the surface is a ridge whose crest holds 10 and 01. Family 2 thresholds the difference x₁ − x₂, which varies along the anti-diagonal: XOR is |x₁ − x₂| = 1, so the surface is a valley with 00 and 11 in the trough and 10 and 01 up the two walls. In the single-input cells the weights are not symmetric, so the fold tilts away from the exact diagonal, but the ridge or valley shape stays.

What decides the family

One number on the hidden unit, and what changes for sigmoid units

The skips can produce any additive pattern on the four rows: a constant plus something in x₁ plus something in x₂. The one pattern they can't produce is the XOR interaction, so the hidden unit has to supply it. Measure what it supplies as

I = h(00) + h(11) − h(10) − h(01)

One hidden unit with skips can realise XOR exactly when I ≠ 0. The output weight must then have the opposite sign to I, and a size of at least about 4 / |I| for a unit margin. That is the proportionality condition: a hinge that barely bends needs a very large u. Everything else is absorbed by the skips.

Sigmoid
The same two families, split by the weight signs. Each appears twice, once with u > 0 and once with u < 0, because a sigmoid is convex below its midpoint and concave above it. The twins are exact: replace h by 1 − h (negate w and b, flip u, add u to c) and the function is identical everywhere. Same realisation, counted twice.
20,000 random units: u sign about 50/50 within each family; twin difference 2·10⁻¹⁵
Step (threshold)
The limiting case. The unit outputs only 0 or 1, so the graded single-input cell disappears, and the 1 − h twin merges the 1-row and 3-row cells. That is where the enumeration's count of 2 comes from.
LP enumeration (results file)

Sigmoid units also realise the graded single-input cell. For example, w = (1, 3), b = −2.5 has a positive pre-activation only on 01 and 11 and gives I = 0.089, so it solves XOR, but only with u ≈ −45. The earlier "threshold / sigmoid: 2 classes" label in the results file applies to step units only. Because a sigmoid is never exactly zero, its cells are defined by where the pre-activation is positive, not by where the unit is silent.

Formalising the equivalences

Four levels, from weaker to stronger

The six classes separate two kinds of symmetry. Reparametrisations (permuting hidden units, rescaling a ReLU unit by k>0 and its output weight by 1/k) leave the function identical everywhere. Task symmetries (swapping inputs, complementing them) preserve the XOR signal on the data but change the function off it. Classes are counted under both, so a class is a family of realisations, and not every member of a class computes the same function off-support.

Minimality and redundancy

A floor you can't go below, and room above it

The floor

With no hidden unit, z is linear in (x₁, x₂), and XOR is not linearly separable. So no realisation has fewer than one hidden unit with skips. Without skip connections the floor is two hidden units: a single unit feeding the output alone gives a function that is monotone in one projection, and that can't produce XOR. Every minimal realisation is one of the six classes above.

Above the floor

Extra hidden units add nothing to the signal. Some can be removed exactly: a unit active on all four rows is linear there and folds into the skips (relay collapse), and two units with proportional incoming weights merge into one, because ReLU(k·a) = k·ReLU(a). Others go only by pruning and retraining. That is not function-preserving: it moves the network to a different realisation of the same signal.

Hidden units per solution. Raw: 2 to 8 (median 6.5). After exact relay collapse plus greedy pruning:

The other 24 kept 2 to 4 nonlinear units: duplicate hinges (the same active set twice in one network, seeds 1, 19, 23, 26: aliases within one network) or mixed decompositions such as OR plus x₁∧¬x₂ (seed 4).
